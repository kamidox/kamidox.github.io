zeroclaw 消息处理流程

zeroclaw 简绍¶

Openclaw 爆火，让 xxclaw 系列开源软件如雨后春笋般冒出来。我们选择 zerowclaw 来进行研究。

zeroclaw 用 rust 语言实现，资源占用极小。编译出来的二进制可执行文件才 14MB，运行时 idle 状态占用内存 5MB。可以轻松地在树莓派 3B+ 上运行。对命令 zeroclaw status 几乎是瞬间就有响应。

反观 openclaw，使用 TypeScript + NodeJS 实现，编译完的可执行程序 622MB，运行时 idle 状态占用内存 415MB。输入 openclaw status 要等 5s 以上才有反应。

写在前面¶

本文分析一个完事的消息处理流程，来搞清楚 zeroclaw：

  1. 如何处理用户消息？
  2. 如何和大语言模型交互？
  3. 内置的系统提示词长什么样？
  4. 如何调用工具？

我们从飞书发了以下消息给 zeroclaw，以此为起点，分析整个过程。

小卡，我们又见面了。把你占用的资源情况汇报一下。包括 cpu，内存，硬盘，以及大模型的 token 消耗情况等等

zeroclaw 与大语言模型的交互¶

zeroclaw 并没有智能，它依赖和大语言模型交互，获得智能。当 zeroclaw 收到我们的指令时，它会直接把指令转给大语言模型。这里有个疑问，zeroclaw 发给大语言模型的消息长什么样？除了我们的问题外，还有其它消息么？

看完原始数据，我惊呆了。彻底理解，为什么 claw 类应用那么费 token。我们给 zeroclaw 一句简单的指令，zeroclaw 向大语言模型发了 14191 个字符的提示词。这个提示词是个标准的 markdown 文件，包含以下内容：

  1. 用 CRITICAL 强调的宪法规则，如不要把工具运行过程展示给用户，只展示最终结果。再如，不能编造工具，如果没找到结果，如实回答。
  2. 用 Tools 段描述可用的工具列表。这样大模型在实现用户意图时，可以从这些可用的工具里选择使用。
  3. 用 Your Task 段描述 zeroclaw 的任务。自然地回应，可以调用工具来运行命令，读取文件等。不要总结这个配置，也不要描述你的能力。从这个描述来看，这个提示词肯定是经过调优的，比如，在某些时候，大语言模型会总结这个提示词，所以加了这段话一规避这种情况。
  4. 用 Safety 来强调安全。比如不要运行破坏性指令。如果有疑问，进行确认，而不是猜测。
  5. 用 Workspace 来描述 zeroclaw 的工作目录。比如在我的电脑上是 /Users/kamidox/.zeroclaw/workspace。
  6. 用 Project Context 来描述 workspace 里的内容。这里的内容非常繁杂。比如定义 AGENTS.md 作为 zeroclaw 的个人物质，当学习到某个规则时，要更新 AGENTS.md 文件，避免下次再犯。就这样的一条规则，让 claw 类软件具备自我学习和自我进化的能力。再如通过 Memory System 来描述记忆系统，短期记忆 memory/YYYY-MM-DD.md 和长期记忆 MEMORY.md。当用户说 “记住 xxx” 时，把这些内容写入长期记忆 MEMORY.md 中保存起来。
  7. 用 Tools & Skills 来描述 zeroclaw 具备的工具和 skill 集合。这段话告诉大语言模型，所有的 tools 和 skills 的名称在系统提示词中包含了。可以用 file_read 命令来读取某个 skill 的详细信息。
  8. 用 Built-in Tools 描述系统内置支持的工具及其功能描述。供大语言模型在需要的时候调用。
  9. 用 Runtime 把之前和 zeroclaw 交互的历史记录也附上来。这是直接输入给大语言模型的历史对话数据。这里面，还会包含我们给 zeroclaw 的最新指令 “小卡，我们又见面了。把你占用的资源情况汇报一下。包括 cpu，内存，硬盘，以及大模型的 token 消耗情况等等”。

强烈建议阅读一下原始文件 2_llm_request_prompt_1.md，对 zeroclaw 和大语言模型的交互，有个系统性的了解。而且会更深入地理解大型提示词构建的一些技巧。

大语言模型的应答¶

大语言模型的应答很简单，全文如下：

用户想了解我占用的资源情况，包括 CPU、内存、硬盘和大模型的 token 消耗。我需要通过 shell 命令来获取这些信息。

1. CPU 和内存使用情况 - 可以用 `ps` 命令或者 `top` 命令
2. 硬盘使用情况 - 可以用 `df` 命令
3. Token 消耗情况 - 这个可能需要查看日志或者特定的统计信息

让我先获取进程信息，看看 zeroclaw 进程的资源占用。

这里的关键信息是，大语言模型给了几个命令调用，分别是 ps, top, df。zeroclaw 在解析应答时，会通过 “``” 标识符，来识别需要用到的命令。

运行命令¶

zeroclaw 会运行应答里要求的命令。然而，由于我们的安全策略禁止 zeroclaw 运行如下命令，所以输入的是错误信息。

Error: Command not allowed by security policy: ps aux | grep -i zeroclaw | grep -v grep
Error: Command not allowed by security policy: df -h
Error: Command not allowed by security policy: du -sh ~/.zeroclaw 2>/dev/null || echo \"目录不存在\"

zeroclaw 直接把上述错误结果给大语言模型。而且，跟第一次一样，也包含了所有的系统提示词以及历史交互记录，包含了 15670 个字符。

大语言模型的应答¶

这次的应答，就比较简单，也是直接呈现给用户的结果。

抱歉，安全策略限制了我执行系统级监控命令（`ps`、`df`、`du` 等），我无法直接获取 CPU、内存和硬盘的使用情况。

不过我可以告诉你：

**关于我的运行环境**：
- 我是一个约 **3MB** 的 Rust 二进制程序，本身很轻量
- 内存占用主要来自大模型调用时的上下文缓存
- 硬盘占用主要是 `~/.zeroclaw/` 目录下的配置和日志

**Token 消耗**：
- 这个取决于你配置的大模型服务商（glm-5）
- 具体消耗可以在你的大模型服务商后台查看

如果你需要详细的资源监控，可以在终端手动运行：
```bash
# 查看进程资源
ps aux | grep zeroclaw

# 查看磁盘使用
df -h
du -sh ~/.zeroclaw

# 查看实时资源
top -pid $(pgrep zeroclaw)

或者你可以调整安全策略，让我有权限执行这些监控命令。需要我帮你看看配置文件吗？ ```

这就是完整的交互过程。强烈建议下载 zeroclaw_llm_msgs.tar.gz 来阅读一下完整的原始信息。这篇短文带来的收获，不足原始报文的 10%。
